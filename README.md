# Лига Героев | Склад мерча

React + Firebase Authentication и Firestore. Firebase Hosting раздаёт приложение, Cloudinary хранит фотографии, GitHub хранит исходный код. Для запуска используется Node.js 22.12+ (или Node.js 24).

## Локальный запуск

```bash
npm ci
npm test
npm run dev
```

Для просмотра с демонстрационными остатками добавьте `VITE_DEMO=true` в `.env.local`. Демо работает с данными этого браузера. При заданной конфигурации Firebase приложение открывает рабочий режим.

## Подготовка рабочего проекта

1. В Firebase Console создайте проект на тарифе Spark и зарегистрируйте веб-приложение. Скопируйте `.env.example` в `.env.local` и заполните поля по конфигурации веб-приложения.
2. В Authentication включите Email/Password. Создайте учётную запись владельца и скопируйте её UID. Доступ выдаётся только учётным записям с ролью.
3. Создайте базу Cloud Firestore по умолчанию в Production mode. В консоли Firestore добавьте документ `members/<UID владельца>` с полем `role` типа string и значением `admin`. Для остальных сотрудников создавайте учётные записи в Authentication, затем назначайте роли по UID в разделе «Доступы».
4. Создайте Cloudinary Free. Укажите Cloud name в `VITE_CLOUDINARY_CLOUD_NAME`. Загружайте фото в Media Library и вставляйте их Delivery URL из этого Cloudinary в карточки товаров. Стандартные Delivery URL доступны по ссылке.
5. Создайте приватный репозиторий GitHub и отправьте в него исходники. Файл `.env.local` исключён из Git. Для публикации выполните команды ниже с доступом владельца к Firebase.

```bash
npm ci
npm run build
npx firebase-tools login
npx firebase-tools deploy --project YOUR_FIREBASE_PROJECT_ID --only firestore:rules,hosting
```

Релиз использует Firebase Hosting на Spark. Подключение платёжного аккаунта и переход на Blaze не требуются.

## Доступ и учёт

- Администратор управляет доступами, каталогом и остатками.
- Редактор добавляет и правит товары, корректирует остатки и проводит перемещения.
- Читатель просматривает каталог, обе цены и историю.
- Отдельный артикул обозначает вариант размера и цвета. Остатки учитываются отдельно в офисе и на едином складе.
- История содержит автора, серверное время, комментарий и снимки до и после операции. Для перемещений обе локации и история обновляются одной транзакцией.
- Редактирование карточки и корректировка остатка вынесены в отдельные операции. Правила Firestore применяют права и проверяют допустимость операции на стороне базы.

## Проверка правил Firestore

Тест выполняется в отдельном демонстрационном проекте эмулятора. Для запуска требуется Java.

```bash
npx firebase-tools emulators:exec --only firestore --project demo-hero-merch "node tests/firestore.mjs"
```
